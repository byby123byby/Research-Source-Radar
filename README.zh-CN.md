# Research Source Radar

**用它找到和你的项目真正匹配的论文、开源项目、数据集、方法和其他资料。**

[快速开始](#快速开始) · [核心能力](#核心能力) · [输出内容](#输出内容) · [迁移完整性](#来源到目标的迁移完整性) · [安装](#安装) · [English](README.md)

</div>

Research Source Radar 帮你找到项目里用得上的论文、开源项目、数据集和方法。它会结合项目目标、当前卡点和使用限制来找，说明每个来源能帮上什么忙，并优先挑出值得深入看的几项。

## 快速开始

普通使用不需要填写结构化表格，直接说：

> 用 Research Source Radar 帮我看看和这个项目相关的论文、开源项目和资料。

已有项目上下文时直接开始；没有时，补一句你在做什么、目前卡在哪里即可。

如果已经有喜欢的来源，或者第一批推荐没对上，可以贴一篇或多篇作为例子：

> 我想找的是这几篇论文、这几个项目这样的。帮我看看它们有什么共同点，再找一些。

它会先核对来源，再把推测的偏好说清楚，让你纠正。你给的例子与新找到的来源会分开标记，不会把你已知的东西算成新发现。

## 核心能力

- **围绕项目找**：根据你要解决的问题寻找论文、仓库、数据、方法、标准和官方资料，不只匹配关键词。
- **继续找能复用的东西**：找到方法论文后，继续查现成实现、数据、模板、更新版本和后续工作，说明哪些能省下重复劳动。
- **跨学科找办法**：不只找同领域、同名称的来源，也找术语不同但问题结构相近的方法。说明两边哪里对应、哪些前提不同，以及如何验证能否借用。
- **热门和冷门都找**：近期论文、项目活跃度和社区关注是独立检索路线；同时保留不热门但有用的来源。说“热门”时，给出具体时间和依据。
- **核对原始出处**：给出论文原文、官方仓库、数据集主页或原始规范；区分同一来源的不同版本，不把一篇论文的多个链接当成多个发现。
- **少数重点，其他按需看**：先解释最值得投入的 3–5 项，再给出其余候选。不因为“相关”就建议每个都深入研究。

适用于计算机、生命科学、健康、社会科学、金融量化、法律政策、人文、艺术、设计、教育及跨学科项目。不同学科使用各自的来源和判断依据，不要求每个领域都有 GitHub 仓库。

## 输出内容

通常给出 10–20 个候选，默认约 12 个；来源不足时说明缺口，不凑数。先列最值得看的几项，再给出完整候选卡。每张卡都写清楚：

- 来源：可直接打开的真实来源链接或稳定标识；
- 是什么：项目、论文、数据集、方法、标准或其他来源的简要说明；
- 为什么现在看：它和当前项目的具体连接；
- 具体时间：首次发表、版本或版次、本次核验日期分别记录；原始来源只提供年份时就写年份，不编造月日；
- 热度/时效说明：热度发生的日期或区间及其依据，与发布时间分开；没有依据就不标成热门；
- 机制标签：它解决了什么机制问题；
- 对目标的价值：直接可用、需要适配重实现、机制参考、轻量参考或待核实，具体能省什么工作、下一步怎么用；
- 现成实现与后续工作：找到的代码、数据、模板、新版本或后继来源；未找到或访问受阻时也说明；
- 风险与限制：证据、实现、数据、平台、许可或迁移方面的风险；
- 建议投入与实际阅读深度：值得看多深、这次实际读到了哪里，分开说明。

你可以用 **夯 > 顶级 > 人上人 > NPC > 拉完了** 给反馈。AI 的推荐理由和你的评分分开记录，不会替你填分：

- **夯**：优先深读，并优先安排迁移或验证；
- **顶级**：高优先级深读；
- **人上人**：机制有明显价值，重点参考或适配；
- **NPC**：相关但只适合轻量参考，不建议平均深入很多；
- **拉完了**：当前任务中不值得投入。

## 来源到目标的迁移完整性

当你要求借鉴一篇论文、一个开源项目、模型、截图或技术线索时，Skill 会先建立来源能力清单，而不是只摘取几个熟悉的机制：

1. 确认来源身份和版本；
2. 先列出论文全文、补充材料、README、相关实现、配置、评测、限制和版本记录，再记录实际读到了哪些、哪些未读或无法获取；
3. 列出关键机制、前提、状态变量、更新规则、验证方式、失败处理、资源/平台约束和评估结论；
4. 逐项映射到目标项目；
5. 将每一项标为直接可用、需要适配重实现、刻意不采用或尚未核实；
6. 为每个“不采用”说明原因；“计划采用”和“已经实现”分开，已实现项需要目标行为映射及验证结果，而不只是文件名或测试名；
7. 仍有未解释项目时，保留为待处理项，不提前宣布完整迁移。

这套流程同样适用于生物方法、金融因子、法学框架、人文理论、艺术工具和其他跨学科来源。

## 用户反馈与偏好

你可以直接说：

- “这个来源一般般”：只降低这个候选；
- “这批推荐一般”：记录为本轮检索失败，诊断遗漏方向后换检索路线；
- “这种机制我想多看”：增加当前任务中相似机制的探索；
- “这类我不想再推荐”：降低相似类型，但不把所有相关标签一并拉黑；
- “我觉得相关的是这几个”：贴出 1–n 个来源，让 Skill 先核验并猜测当前任务的偏好。

如果整批结果不符合预期，Skill 会先问一两个关键问题，或请你贴出想要的来源，再换方向搜索，不让你填写一长串表格。

持久保存的偏好来自你可核对的原始标注和理由，经你确认后才影响后续检索与排序。偏好保存在当前项目的本地文件中，可查看、可删除，不串到其他项目。“可以看看”不会被当成强烈喜欢，“暂时没用”也不会把所有相关方向一起排除。

## 安装

将本目录安装为 Codex Skill：

```text
$CODEX_HOME/skills/research-discovery-and-translation-audit/
```

原生 Agent Skills 宿主可使用内部兼容名称 `$research-discovery-and-translation-audit`；实际使用时直接说“用 Research Source Radar”即可。
